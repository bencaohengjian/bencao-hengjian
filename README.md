# 本草衡鉴 · 在线版（四学科）（链接分享、付费开通）

> 2026-11-20 起支持四学科：中药药理学（550 题 / 404 卡）、中药炮制学（357 题 / 63 卡）、中药鉴定学（447 题 / 486 卡）、药用植物学（302 题 / 161 卡），首页顶部芯片切换，支持单科开通或全科开通。

一个纯静态网页 App：手机浏览器打开链接即用，无需安装、无需小程序审核、不需要服务器。
刷题支持「做题 / 背题」双模式：做题提交判对错、错题入本；背题点开即显示正确答案与解析（简答论述直接展开答案），可一键「遮住答案」自测；背题顺序可选顺序或随机，进单元自动打乱，答题页还能随时点「打乱」从头再背。试看每科前 2 个单元与前 2 章知识卡；付款后给对应套餐的开通码，输入即解锁所选学科；全科码解锁四科全部 1656 题（药理 550＋炮制 357＋鉴定 447＋植物 302）、1114 张知识卡（404＋63＋486＋161），并可按知识点一键生成同考点新题（举一反三，药理、炮制、鉴定三科均已支持，每卡 3–6 道）。

## 一、线上结构

```
index.html        页面结构（标题、tab、试看条）
app.css           墨绿＋铜金配色，宋体
app.js            逻辑：试看门禁、开通码校验、AES 解密全量、刷题、错题本
trial.json        试看数据（明文，约 52 KB）
full.enc          全量题库与知识卡（AES-256-GCM 加密，约 974 KB）
variants_yaoli.enc / variants_paozhi.enc / variants_jianding.enc / variants_zhiwu.enc
                  举一反三变式题（按学科单独加密，点按钮时只下载当前学科，约 0.25–1.5 MB；植物学暂未配变式，按钮不显示）
```

所有文件平铺在仓库根目录（不放 data/ 子目录），页面用相对路径 `trial.json`、`full.enc`、`variants_<学科>.enc` 读取，换到任何静态托管都能用。

### 举一反三（按知识点出新题）

- 三科现有变式：953 个知识点、4417 道变式题（药理 1433、炮制 378、鉴定 2606）；植物学 161 卡暂未生成变式，药理平均 5.2 题/知识点，炮制每卡 6 题，鉴定每卡 3–6 题。
- 打开「知识点」→ 选章 → 点开一张卡 → 卡片底部出现「举一反三 · 用这个知识点出 N 道新题」。
- 题型分三类：正向（某药的来源/性状/功效特征是？）、反向（这句特征描述的是哪味药？）、术语定义（某术语是指？）。正确项与题干均取自卡片原文，干扰项取同章节其它药材的同类原文，不拼半句、不编造。
- 变式题按学科分三个文件，首次点击「举一反三」时只下载当前学科并解密，不拖慢首页、不占手机流量。

## 二、卖一单的动作

1. 用户下单付款（站外：闲鱼/小红书/微信）。
2. 你从《本草衡鉴_开通码_首批20个.csv》里取一个没用过的码发给他，同时在表里把状态改成"已售 + 日期"。
3. 用户打开链接 → 「我的」→ 粘贴码 → 开通。授权记在**他自己的浏览器**里，刷新、关页面都不掉。
4. 到期前 7 天页面顶部会自动提示；到期后自动回到试看，需要换新码。

**套餐与码的格式**：`ZY-到期日-序号-套餐-校验位`，套餐为 `Y` 药理、`P` 炮制、`J` 鉴定、`Z` 药用植物学、`A` 全科。
例如 `ZY-20271231-02-Y-496E`（药理单科）、`ZY-20271231-02-A-78A6`（全科）。

- 单科码只解锁该科全部单元、全部知识卡和举一反三；未开通的学科仍可试看前 2 单元、前 2 章，芯片上带 🔒。
- 同一浏览器再输第二个单科码会自动**合并升级**（如先 Y 后 P = 药理+炮制），有效期取较晚的一个；输全科码直接升全科。
- 老格式 `ZY-到期日-序号-校验位`（无套餐段）继续有效，按**全科**处理，不影响已经卖出去的码。

**本轮演示码（到期 2027-12-31）**：`ZY-20271231-02-Y-496E` 药理 / `-P-B934` 炮制 / `-J-E530` 鉴定 / `-Z-80DD` 植物/ `-A-78A6` 全科 / `ZY-20271231-02-ED2E` 老码全科。

需要新码时告诉助手："生成 10 个到期 2027-06-30 的码"，会按序号续排并给 CSV。

## 三、更新资料（不用重新部署页面）

1. 改 `云端素材_上传用/全量/tiku.js` 或 `zhongyao.js`；
2. 跑 `node 工具/导出云端数据.js`，再跑 `node 工具/生成在线版.js`；
3. 把新生成的 `trial.json`、`full.enc`（如改了变式题再加 `variants_yaoli.enc`、`variants_paozhi.enc`、`variants_jianding.enc`）上传覆盖到仓库根目录（GitHub 网页上传即可）；
4. 同时把 `app.js` 里 `CONFIG.BUILD` 改成新日期，避免浏览器继续用旧缓存。

已开通用户刷新即见新内容，不用重新买、不用重新发码。

## 四、代价与边界（必须知道）

- **没有服务器，就没有真正的"卡密验证"**。校验逻辑在网页里，密钥也在网页里；懂技术的人可以伪造码，也能在解锁后把数据存下来。它防的是"随手转发给同学"，防不了"专业倒卖"。要真防，必须上服务端（云函数或轻服务器），这是成本与收益的取舍。
- **授权只认浏览器**。换手机、换浏览器、清缓存都要重新输入同一个码（不额外收费）。同一个码可以被多人同时用，目前没有设备数限制。
- **公开仓库 = 密钥公开**。想让门槛高一点，可以后期改成"码 + 服务端校验"，或把仓库设为私有（GitHub Pages 私有仓库需要付费账号）。
- **平台合规**：不要在商品标题/详情里写"押题、保过、内部资料、官方指定、真题原题、独家"。
